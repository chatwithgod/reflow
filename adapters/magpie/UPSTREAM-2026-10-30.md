# Magpie 2026-10-30 上游适配

本轮固定 [Magpie `ffa07395eb274cbe6cea299d825bf4f5c58db6e2`](https://github.com/yetone/magpie/commit/ffa07395eb274cbe6cea299d825bf4f5c58db6e2)，这是核对时的上游 main。该提交新增 Codex 到 Magpie 的 Responses WebSocket 入口，后续轮次可只发增量历史。上游比原基线 `a1174674` 多了 721 个提交；旧基线及七份补丁原样保留，新版放在 [2026-10-30 清单](patches/2026-10-30/manifest.json)。两套补丁不能混用。

## 改动与边界

宿主执行扩展接入点按新源码位置迁移。新 WebSocket 入口先把连接内的历史补齐，再进入原有请求、签名、传输和 Reflow 流程；不需要改 Reflow 核心，也不改变续接判定条件。中间轮的工具调用继续被丢弃，保留的工具调用及其结果只进入下一轮一次。

新增检查覆盖原生下游 WebSocket、上下游均为 WebSocket，以及 Magpie 管理的 Responses 上游。与既有 HTTP、zstd、上游 WebSocket、托管 HTTP 四条路径合计七条模拟路径，都核对同一账号、一次续接、工具隔离、完整历史和宿主用量。另检查：

- 预热在本地完成，不调用上游；随后只发增量的请求能保留预热输入。
- 其他 WebSocket 连接不能复用当前连接的响应历史。
- 中断可见响应时，隐藏续接随之取消；被中断的响应不能作为下一轮父响应，连接仍能服务新的完整请求。
- 故意关闭执行扩展、故意重复追加增量历史，两种故障都使新检查失败；恢复源码后通过。

替代模块文件从新基线的 `go.mod`、`go.sum` 重新生成，继续固定公开 Reflow `v0.0.0-20261028113656-6d8e7a534060`。默认模块文件与上游相同；不依赖本地 Reflow checkout、`replace` 或 Go workspace。设置翻译和原来的测试修正随补丁移植。

## 验证

补丁目录的 Git 属性扩展到日期子目录，保持补丁字节及其上下文空白，不进行换行转换。使用 `core.autocrlf=true` 检出新旧两套共 14 个补丁后，所有散列仍与各自清单一致；没有改写旧补丁。

Windows 普通构建/vet、Windows 与 Linux 的 `nogui reflow` 构建/vet 均通过。扩展生命周期和默认关闭检查 8 项通过 race，用量检查 1 项通过 race。Chromium、WebKit 各 5 个页面通过项，覆盖五种语言的 Reflow 设置及相邻插件页面；所有检查前后的默认及替代模块锁文件保持一致。

完整宿主检查在会话中断后停止，已核对原运行进程不再存在，尚无完整结果。中断前观察到 8,843 个通过项、390 个跳过项、51 个失败项，停在 GUI 包；这些是局部计数，不能当作完整测试结果。已有定向、race、构建和页面结果保留，计划中的新失败对照未启动。本次没有重跑已完成检查。完整来源及范围见[机器证据](../../docs/evidence/magpie-upstream-2026-10-30.json)。旧基线的 12,219 通过、615 跳过、36 失败属于历史记录，不能当作新基线结果。

已读日志中，新出现的 GUI 失败有 15 项明确停在创建测试符号链接时，错误指向缺少权限；这不代表对应页面行为已经执行。Hermes、连接交接、文件读取及其他失败尚未完成原因对照，不能一概归为环境问题，也不能据此排除适配影响。[上游 issue 4115](https://github.com/yetone/magpie/issues/4115)记录过相同 Hermes 失败；本次读取时没有评论或修复补丁。未提交上游反馈。

中断测试的临时目录清理被自动审批拦截，仅返回 `blocked by policy`；未执行删除或尝试其他删除方式。该清理事项不改变已保存的测试结果，目录状态另记在机器证据中。

可用现有隔离入口重现定向检查：

```sh
python scripts/check-magpie.py --magpie /absolute/path/to/patched-magpie --go /absolute/path/to/go --modfile go.reflow.mod --phase suite --tags "nogui reflow" --serial --packages ./internal/gateway --run "TestReflow|TestExecution|TestResponsesSocket"
```
