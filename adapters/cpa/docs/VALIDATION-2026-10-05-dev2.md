# dev.2 · 默认自动模型匹配与隔离验证

日期：2026-10-05。开发构件 `0.1.0-dev.2`，Windows amd64；CPA / SDK `8.0.13`，宿主 commit `d7914afd`。

## 需求与实际实现

用户报告 dev.1 的 HTTP 和 WebSocket 均能成功通信，真实 516 尚未测试，并提出默认免手写配置、随 CPA GPT 模型使用的优化。
固定 SDK / ABI 没有直接查询模型目录的插件回调；本版选择按请求名称自动匹配，而不是声称已精确同步目录。

- 新配置仅需宿主启用开关，默认 `auto`，没有硬编码模型名单。
- 匹配小写 GPT-5 及以上标准名称，支持路由前缀与末尾推理后缀，仅用于选择，不改请求 ID、不解析任意别名或能力。
- 排除名称含已列出的非文本系列词段；命名启发式不等同于模型能力检测。
- 原生 CPA 保持模型可用性检查、别名映射、账号和上游路由职责。没有增加管理 API 轮询、密钥读取或模型注册。
- 旧的 models-only 显式白名单保留精确匹配，含旧空名单回退；显式 `auto` 忽略保留名单，显式 `manual` 空名单不接管。
- `exclude_models` 在两种模式下都优先。注册元数据提供 `auto` / `manual` 枚举，实际 ECPA 界面渲染未自动验收。
- 不改变加密状态、增量请求、协议和流式守卫，不改变折叠/解码器。默认最多追加三轮、最高 tier 6，最低思考 token 实验仍关闭。

自动模式集成回归还断言：

1. 新标准名称无需修改名单；前缀/后缀不影响原生 CPA 的别名映射。
2. GPT-4o 和任意非标准别名不接管；旧名单不会因更新构件而扩大。
3. 配置热重载后显式 auto 覆盖保留名单、排除项优先、显式空 manual 不接管。
4. HTTP 和 WS 均能将合成 516 续为两轮，临时回答被丢弃，最终文本和累计用量保留。
5. 合成 516 缺少 `encrypted_content` 时，HTTP / WS 都只有一轮，正常回答，不追加调用。
6. 连续命中截断启发式时，HTTP / WS 都最多四轮（初始一轮 + 默认三轮追加）。
7. WS 客户端和上游均完成实际握手，断言没有 HTTP 回退；保留单终止事件、序号和 response ID。

`gpt-7-fixture` 等未来名称仅为合成规则测试，不声称该模型存在或已在线验收。
