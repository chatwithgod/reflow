# 本地开发候选包，不是商店正式版

本包不会自动安装、启动或启用插件，不会修改 CPA / ECPA / Codex 配置。
`local://codexreflow` 是本地开发来源标记，不是一个已发布的 GitHub 项目。
实际版本及逐文件 SHA256 见 `manifest.json`；ZIP 校验值见旁边的 `checksums.txt`。

## 当前范围

- 包内 DLL 需与原生 ABI 和真实隔离 CPA 的测试报告 SHA256 相同，打包器拒绝混用不同构件的证据。
- `evidence` 只保存报告类型、场景执行数、宿主版本和报告 SHA256；不打包原始日志、配置、路径或账号。
- 合成测试不是模型质量、计费、Desktop 或生产可用性验收。`live_model_acceptance: pending`。
- 按次诊断说明见 [DIAGNOSTICS.md](DIAGNOSTICS.md)。保持原续接策略，不保证不再出现 516。

## 如需本地试装

必须另行明确授权，并选择没有活动请求的时段；配置重载可能关闭宿主原生 WS 会话。

1. 先记录 CPA 版本、插件当前启用/生效状态、现有 DLL 路径及哈希。
2. 备份当前配置及旧 DLL。不要覆盖、删除旧版本，不要同时启用 CodexComp 和 CodexReflow 接管同一模型。
3. 校验本包哈希；只添加版本化新 DLL，并按当前 CPA 支持的本地插件版本选择方式切换。
   不顺带更改其他插件、账号、传输设置或模型配置。
4. 读回插件注册版本、哈希和生效状态。仍需真实聊天验证，这一步不能由“进程正常”替代。
5. 持续使用已有聊天观察；如果旧 WS 已重载关闭，应重新连接并完整重放上下文，不能删父 ID 后只发增量。

若有回归，恢复原版本选择和必要的配置备份，读回旧 DLL 的版本/哈希/生效状态并验证正常聊天。
恢复备份前先对比配置，保留备份之后用户对其他设置的修改。不要直接用过期整份配置覆盖当前环境。

## 发布限制

不要把本 ZIP 当作商店包上传。正式发布仍需确认仓库归属、公开范围和发布授权，并使用独立的
`package_release.py` 校验正式版本及真实 GitHub 来源。本地候选打包不构成推送、Release 或商店提交授权。
