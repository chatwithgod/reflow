## 桌面隔离入口的核对

只读检查当前安装包，仍能找到 `CODEX_HOME`、`CODEX_ELECTRON_USER_DATA_PATH`、`CODEX_CLI_PATH` 和 `CODEX_APP_SERVER_FORCE_CLI`。启动代码在单实例锁判断之前选择用户数据目录；环境重载时，保留显式 `CODEX_HOME` 还依赖同时指定 Electron 用户数据目录。

11 月 5 日补充：发现 `CODEX_APP_SERVER_FORCE_CLI=1` 还会取消 dot 云端任务连接，因此新的隔离启动候选移除了该参数，继续显式指定本地 CLI 和配置目录。新候选目前只有离线验证，见[后续记录](DESKTOP-DOT-2026-11-05-FOLLOWUP.md)；以下保留本页准备时的检查范围。

这些是当前包的源码观察，尚未运行 GUI 验证，也不是跨版本稳定接口的承诺。官方文档说明 [CODEX_HOME 可以选择其他配置目录](https://learn.chatgpt.com/docs/agent-configuration/agents-md)，但这不足以证明桌面的全部状态或云端授权一起隔离。

官方 [dot 电脑连接说明](https://learn.chatgpt.com/docs/dots/computers-and-apps)另行规定：个人电脑连接是持续的授权，只能连接一台个人电脑，并与 Codex 远程连接或 Work Sync 分开。由此需要分别核对本地配置隔离和 dot 的电脑连接，不能仅凭候选环境变量认定两者均已隔离。

本轮界面工具仍不提供原生窗口控制。浏览器清单中能看到已有 dot 网页，但没有打开该页面或读取聊天，也没有改动其连接。网页入口存在不能证明它经过独立 Reflow。

## 待具备界面操作条件后的最小验收

用户此前选择暂缓手动配合，本轮保留这个安排。以下是准备好的验收顺序，尚未执行：

1. 先在明确隔离的空白桌面配置中核对实际 `CODEX_HOME`、Electron 用户数据目录、后端进程及版本；在隔离成立前不复制真实登录、不连接 dot 电脑，也不关闭现有桌面。
2. 隔离经运行证据确认后，再按该步骤的授权验证原生 ChatGPT 登录与独立 Reflow 路由。配置必须保留 `openai` 身份，并用该隔离 Reflow 的计数确认请求实际经过代理。
3. 在界面观察 dot 入口、账号状态及目标电脑，分别记录哪些只是可见、哪些已连接、哪些确实执行了任务。不能把现有生产入口的成功当作隔离环境的验收。
4. 需要真实任务时，继续遵守并发 1、禁用子代理、每个模型会话最多 180 秒、每轮最多额外续接一次、遇限流停止的约定。续接、工具成功、匹配回传和正常结束必须在同一会话出现；未自然触发时如实记录。
5. 结束后检查生产配置和登录文件、隔离进程与目录清理情况。任何未实际观察的界面行为继续标记未验收。

这份准备记录不代表已经授权或执行 Desktop/dot 接入。原生 CLI 的持续测试授权保持不变；远程推送、发布和正式申请仍按各步骤的实际授权处理。原生真实累计仍为 23 次会话、122 次已观察请求、4 次续接，没有因本轮模拟检查增加。
