## 联调中发现并修复的问题

原先只测试安装和手动启动 stdio，无法证明 Codex 会加载插件。加入真实会话验收后，发现便携插件命令中的 `${PLUGIN_ROOT}` 被当前客户端拒绝，现改为 `./bin/reflow`。随后加强配置路径断言，又发现 MCP 子进程未继承自定义 `CODEX_HOME`，现通过宿主提供的安装缓存路径定位所属目录。

加载插件的 Codex 会话还会执行工作区路由发现。测试使用本地 TLS 服务、临时生成的 CA 和合成账号来覆盖此流程；CA 仅传给测试子进程，没有改系统信任库。当前会话通过 Code Mode 调用插件，测试核对真实健康请求次数、返回结构和配置路径，避免把错误文本中的标记误判为成功。
