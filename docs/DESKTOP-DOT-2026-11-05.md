## 人工观察

用户在独立空白配置中完成 ChatGPT 登录，随后确认“已登录，看到 dot，页面无报错”。这一步的模型入口保持关闭，没有发送模型任务，也没有连接或切换 dot 的电脑。限时检查结束后，测试进程清理为零。

检查期间，生产窗口曾与测试窗口一起显示工作空间设置错误。生产日志中的官方账号、设置接口 429 和 Cloudflare 验证标记早于测试窗口启动；生产窗口后来点一次“重试”恢复，用户确认 dot 也恢复。这个时间关系不能证明账号受限的具体原因，也不证明两个窗口的云端状态相互独立。

隔离范围是显式的 Codex 配置目录、Electron 用户数据目录及子进程环境，仍使用同一个 Windows 用户。不能据此宣称完整 Windows 账号或云端授权隔离。

## 已修正的测试环境问题

1. 原先只建立了空白用户目录，缺少 `Desktop` 等 Windows 常用目录。现已补齐；七个原生 Known Folder 查询均解析到存在的测试目录。文件选择器和窗口响应性仍需界面复测。
2. 启动环境白名单误删了原有代理变量。测试后端与 Reflow 没有继承现有本机代理，日志出现模型列表超时和 WebSocket 502。修复版只在子进程中继承经检查的现有回环代理设置，没有修改系统代理或切换出口。
3. 原先依赖流计数判断失败，无法及时覆盖升级前的 WebSocket 错误；且先清理桌面再停代理，给客户端留下了继续重试的时间。修复版增加原生传输错误观察，先停测试代理，再清理窗口和还原测试配置。原生客户端的内建重试配置未改，不承诺一次失败只对应一次网络尝试。

上述修正已完成以下无账号检查，未启动桌面或新增真实模型请求：

- 实际发布版 Reflow 的 HTTP 和 WebSocket 拨号均进入本地合成 SOCKS 服务。模拟服务主动拒绝连接，未向外部建连；这证明代理环境被使用，不证明官方上游或 TLS 已成功。
- 合成客户端连续尝试八次；先停代理后，慢速清理期间新增的上游请求为零。首次控制夹具观察期限过短的记录保留，后续缩短本地连接等待，未放宽请求数断言。
- 代理已停止时，测试配置仍能精确还原。新错误观察能忽略旧记录和无关 MCP 错误，识别新发生的模型传输失败。

原先运行的脚本和失败记录保留，修正版另存。新脚本通过本地预检，尚未进行修复后的人工界面或真实任务验收。
