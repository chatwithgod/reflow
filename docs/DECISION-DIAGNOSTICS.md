# 续接决策数字诊断

本地 dev.5 候选为独立服务的可选 `/metrics` 增加实际决策计数。此改动只观察核心已经作出的决定，没有修改 `core/`、触发公式、档位窗口、加密推理重放或续接预算。默认仍不开启指标。

`diagnostics_version=1` 时，`fold_decisions` 提供固定数字字段：

| 字段 | 对应的实际核心决定 |
| --- | --- |
| `continue` | 核心返回了下一轮请求 |
| `rule_not_matched` | 用量特征或配置档位窗口未匹配 |
| `no_encrypted_content` | 没有可重放的加密推理项 |
| `max_continue` | 本次响应的续接预算已经用完 |
| `unresolved_parent` | 父响应历史无法完整恢复 |
| `upstream_tool_already_executed` | 上游托管工具已经执行，不能丢弃再重放 |
| `upstream_terminal` | 收到失败或未完成的终止状态 |
| `other` | 未识别的内部原因；不记录其原始字符串 |

这些计数来自 HTTP/SSE 和 WebSocket 路径里的实际 `Finish` 结果。透传、WebSocket 预热、核心没有完成决策的取消或异常流，不会编造一个停止原因。决策计数不保证等于请求总数；“决定继续”也不单独证明下一轮已经成功送达或工具执行成功。

`reasoning_token_samples` 最多保留本进程前 64 个有效、明确报告的推理 token 数；超出部分计入 `reasoning_sample_drops`。有效用量缺少推理字段时计入 `reasoning_missing_reports`，不冒充 0 token。样本按终止用量的观察顺序排列，不能当作请求 ID、模型或账号的对应表。仅记录数字，不记录推理正文、密文、调用标识或凭证，也不落盘。

新增 Python 读取器只接收已知计数、最多 64 个整数及固定字段名，遇到不认识的版本或非法字段会标记诊断无效；dev.4 缺少该组字段时仍可正常读取原指标。现有评测时间线、评分和验收规则不变。

本机干净源码副本的普通/race 检查各 **79 通过、4 跳过**，vet 与解码 fuzz 通过。包括缺少密文、预算用尽、未知父响应、托管工具、失败终止、HTTP/WS 决策、预热排除、样本上限、重复终止、快照隔离及并发读取检查。首次直接全量检查误扫了被 Git 忽略的历史故障注入源码；最终检查逐文件复制当前已跟踪和非忽略的新源码，并核对散列，原诊断文件未删除。

Windows amd64 候选的独立程序和 Codex 插件包已完成提取验证：原生客户端普通/race 各 10 项通过，五个写入场景全部通过，测试串行、合成登录、真实模型调用 0。评测器使用旧 dev.4 和新 dev.5 各通过 26 项检查，打包程序的 `/metrics` 也确认能被新读取器识别。此候选的其他平台尚未运行，未发布。完整散列与范围见[dev.5 离线证据](evidence/decision-diagnostics-dev5-2026-10-30.json)。

随后依据用户持续授权完成了两次有限真实诊断：[对账任务](LIVE-LEDGER-DEV5-2026-10-30.md)的 7 轮均未匹配规则，[构建计划任务](LIVE-SCHEDULER-2026-10-30.md)出现一次自然续接，但命令失败使严格验收未通过。新观测不能补回旧测试没有记录的数据，也不保证之后一定自然触发续接。后续不再逐轮申请授权，继续保留并发 1、独立临时环境和既定停止条件。
