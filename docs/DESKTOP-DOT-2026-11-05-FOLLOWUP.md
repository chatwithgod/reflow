## 复验的云端连接问题与代理修正

第二次任务移除了强制 CLI 参数，但仍失败。桌面日志在云端 `durable` 连接建立前记录 `WebSocket was closed before the connection was established`，后续项目关联也遇到同一错误。dot 没有返回随机标记，本地 Reflow 推理请求为 0。控制器在准备等待上限退出，退出原因为 `setup_idle_limit`；测试进程清理和保护文件检查通过。

检查当前安装包后发现，云端 WebSocket 的 Node HTTP(S) Agent 只有在设置 `NODE_USE_ENV_PROXY` 时才读取代理环境。本次子进程原先继承 SOCKS 代理地址，并且缺少这个开关；本机 Windows 已有可用的回环 HTTP 代理地址。新环境仅为隔离子进程设置现有 HTTP 代理、`NODE_USE_ENV_PROXY=1` 和本地 `NO_PROXY`，继续保留正常 TLS 验证。没有修改注册表、系统代理、生产 Codex 配置或已安装客户端。Node 官方说明中的开关和代理配置见[企业网络配置](https://nodejs.org/learn/http/enterprise-network-configuration)。

用同一包内 Node `v24.22.1` 和仅回环的 TLS/WebSocket 升级夹具检查四种情况：HTTP 代理加开关产生一次 CONNECT；未启用开关、SOCKS 地址及本地 `NO_PROXY` 的三个对照都未经过代理。四次握手 TLS 验证均通过。最初夹具误以为 SOCKS 会抛出配置异常，实际观察到直接连接，因此保留首轮失败，修正对照预期后四项通过；这不是官方云端连接通过的替代证据。

随后只打开窗口、不发送任务的三分钟观察没有触发云端握手，在时间上限退出，不能判为云端连接成功或失败。真正的连接成功出现在下面的单任务复验中。
