## dot 的已验证范围

用户先在原窗口收到固定连通性回复，随后看到 dot 云端电脑由“离线”变为“已就绪”。本机设备显示在线，菜单只有“取消访问权限”；本轮保留该授权，没有连接、切换或撤销设备。

之后在接入独立 Reflow 的隔离窗口中，只发送一次读取合成随机标记文件的要求，并明确禁止另建任务、修改文件或启用子代理。dot 正常回复，表示读取本机文件需要新任务，并按要求停止。没有返回随机标记，不能认定读文件通过。

该轮停止代理前的最后一次采样中，Reflow 推理请求和续接计数均为零，预热计数为 2；这不代表 dot 云端没有模型调用。dot 云端模型及后台活动不由本地测试控制器计时或终止。收到用户反馈后，本地控制器停止代理并清理测试窗口，测试进程为零，保护文件未变。见[dot 机器证据](evidence/dot-compat-2026-11-05.json)。

官方文档区分 dot 自己的云端电脑与获得授权的个人电脑，也说明 dot 的个人电脑授权和 Codex 电脑连接相互独立。因此，隔离后端的远程控制状态不能单独证明 dot 会把新任务交给哪个后端。这一阶段尚未建立 dot 已授权设备与独立 Reflow 测试后端的对应关系。[官方电脑与应用说明](https://learn.chatgpt.com/docs/dots/computers-and-apps)

## 授权后的本机任务与测试脚本修正

继续检查已安装版本后，确认 dot 电脑状态来自单独的本地执行器服务。测试窗口和原窗口使用不同的安装身份，各自有桌面进程启动的 `exec-server`。用户在测试窗口看到“允许访问”，确认此前的测试实例尚未获得 dot 电脑授权；这解释了为什么不能把原窗口的已有权限当作测试实例的权限。

用户随后明确允许本轮临时授权并恢复原连接。在测试窗口完成授权后，只发送一次创建本地 Codex 聊天的要求：使用已有 `work-reflow` 项目，仅运行固定脚本读取合成随机标记，不改文件、不启用子代理、不自动重试。dot 先表示正在创建，随后报告内部错误，没有给出执行结果。

同一时间的桌面日志记录到 `taskProject/assign` 返回 `thread not loaded: <id>`。停止代理前的 Reflow 推理请求为 0，本地模型计时未开始；隔离会话记录没有新用户轮次，原窗口和隔离配置的原生状态数据库均没有该错误关联的聊天 ID。不能据此否定云端已建立聊天记录，也不能把 dot 的“已创建”回复认定为任务执行成功。云端模型调用数未观测。

具体测试环境问题是启动时设置了 `CODEX_APP_SERVER_FORCE_CLI=1`。已安装版本的路由选择函数首先检查此标志：它会同时取消本地和云端宿主的 WebSocket 路径；而上述项目关联处理明确通过云端 `durable` 宿主读取聊天。这说明该参数会破坏本次需要的云端任务连接，与已观察错误吻合；是否是全部原因，仍待修复后的实测确认。

新的环境候选移除该强制参数，保留显式的包内 CLI、隔离 `CODEX_HOME`、Electron 配置目录及现有代理。当前 Windows 分支不会启用源码中仅面向非 Windows 的本地 daemon 复用。离线执行已安装版本的路由选择函数，六个受控宿主夹具全部符合预期：原标志关闭云端 WebSocket，移除后允许云端按原有 URL 连接，本地未设置 WebSocket URL 时继续走 CLI。宿主分类在夹具中使用受控函数；这不是实际桌面或云端连接验收。新启动和恢复入口的原生 cmd 预检、固定读取脚本检查均通过，没有新增真实模型调用。

本轮原生模型请求仍为 0，随机标记没有返回，六个原夹具文件未变。用户已确认撤销测试实例授权，原电脑在线且已有访问权限；测试代理、任务窗口和恢复窗口均退出，三个生产保护文件未变，隔离配置精确还原。失败记录、清理结果和修正候选的边界见[本机任务机器证据](evidence/dot-task-2026-11-05.json)。旧脚本和旧证据保留，新候选尚未进行真实复验。
