# Windows 原生写文件离线复现

2026-10-26，两版官方 Codex CLI 的 `apply_patch` 写文件探针均失败，经过和绕过 Reflow 都能复现。已定位到文件系统 helper 遗漏 `SYSTEMROOT` 的启动故障。2026-10-27，将上游修复加入隔离源码构件后，五个写入场景全部通过；这是本地构件的离线结果，真实账号会话仍未完成整体验收。

2026-10-29 补充：未修改的官方 `0.165.0` 与应用附带的 `0.165.0-alpha.1.2` 均已通过同样五个写入场景、无账号预检及协议/插件 race 检查。见 [新版本独立记录](NATIVE-CLIENT-2026-10-29.md)。下表继续保留旧版本的实际结果；新结果不等于 Desktop/dot 或真实续接会话已验收。

## 已确认的 helper 启动故障

直接调用两版 CLI 的本地 stdio exec-server，在同样的 MXC 文件写入路径得到底层错误：显式子进程环境缺少 `SYSTEMROOT`。官方 `0.164.0` 源码的文件系统 helper 白名单确实漏掉这个变量；补丁工具仅显示外层写入错误。

控制实验保持文件和网络权限不变：缺少该变量时无法启动；仅保留宿主的 `SystemRoot` 后，允许目录内写入成功；目录外写入仍被拒绝。随后查到 OpenAI 已合并 [修复 #56468](https://github.com/openai/codex/pull/56468)，但已测两版 CLI 和另行检查的 `0.165.0-alpha.1` 源码仍缺少该变量。已将上游原始修复加入隔离构件并完成上表复测。见 [复现脚本与上游修复记录](../contrib/codex-windows-mxc/README.md)。以上检查均无账号和模型调用，也不把上游已有修复计作本项目的新贡献。

## 修复构件的验证范围

本地构件以 `rust-v0.164.0` 的固定提交加上游 `d4bdafd` 修复构建，包含同版本 `codex.exe` 和 `codex-code-mode-host.exe`。环境过滤单测 1 项通过；本地文件系统 RPC 确实写入成功；上述五个原生写入场景、直接 MCP、Code Mode 协议回归及原生插件安装与 stdio 验证均通过。

最初只构建了 CLI，缺少 Code Mode 宿主，五个场景因此未到达写入工具，全部按失败保留。补齐配套组件后重新运行通过，没有修改测试断言或放宽沙箱权限。原官方 CLI 未被替换，Reflow 仍使用此前同一个 dev.3 构件。

这些结果证明覆盖场景中的续接、原生工具执行、文件读回和下一轮工具结果回传能完成；它们不证明真实模型会触发续接、质量会改善，或此前超时已经修复。

2026-10-27 后续真实诊断中，隔离修复版完成了一次原生文件修改，工具失败事件为 0，文件评分 9/9，并正常结束。此次续接为 0 次，所以不能补齐真实续接验收或证明历史超时根因。见 [单次实测](LIVE-SMOKE-2026-10-27.md)。

## 其他已排查因素

- 保留 `SystemDrive` 后，MXC 的固定命令写入预检通过；本探针已保留该变量。
- MXC 内的 PowerShell 为 `ConstrainedLanguage`：直接调用 `.NET` 写文件方法报 `MethodInvocationNotSupportedInConstrainedLanguage`，而 `Set-Content` 和 `cmd` 重定向均能修改宿主工作区文件。上述原生补丁路径使用 Rust helper，不能用这个 PowerShell 限制解释其环境变量遗漏；没有修改系统语言策略。
- 早期绕过代理的用例先在模拟账号路由阶段失败，不能用作文件写入对照。修正本地 TLS 账号查询后，才得到上表所列结果。

真实测试没有保留工具错误正文，模拟上游也不包含真实服务的全部元数据。因此这些结果不能证明真实测试中的工具失败或 180 秒超时由同一问题导致，也不能证明 Reflow 在所有真实路径中无关。真实追加诊断正常结束但未触发续接，结论仍见 [真实测试记录](LIVE-SMOKE-2026-10-26.md)。

## 复现入口

设置 `REFLOW_CODEX_BIN` 指向待测 CLI；可选 `REFLOW_PROXY_BIN` 指向打包 Reflow，未设置时使用测试内代理。然后在项目根目录运行：

```powershell
go test -tags native_write_probe ./integration -run '^TestCodexNativeWriteProbe$' -count=1 -timeout=5m -json
```

五个场景串行执行。补丁失败会使此命令返回非零退出码，没有被改写为跳过或预期成功。测试仅使用临时目录内的合成登录信息；所选 CLI 及其配套组件决定实际结果。

默认 `scripts/verify.ps1` 不包含这个显式构建标签。dev.4 完整结果为 76 个通过项、0 跳过，race/vet/fuzz 通过；本页五个写入场景也已使用 dev.4 单独复测通过，不能混作同一次全量测试。新评测器还在读取账号前检查配套宿主和文件系统写入边界：原版准确报告 `missing_systemroot`，隔离修复版通过。见 [dev.4 记录](VERIFICATION-0.1.0-dev.4.md)。下一步仍需验证真实续接后的完整会话；真实调用须另行授权。
