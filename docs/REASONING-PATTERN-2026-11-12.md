# CPA 用量记录中的 `518n−2` 出现比例

这份统计用于说明 Reflow 触发线索在一套实际使用记录中出现了多少次。它是观察性统计，不是插件开关对照，也不估计模型能力或回答质量。

## 数据范围

读取维护者本机 CPA/ECPA 的 `usage_events` 表，使用 SQLite 只读连接和同一个读事务。没有调用模型、改变 CPA 配置或导出原始行。公开文件只有模型名称、日期范围和汇总计数，不包含账号、凭据、请求标识、提示词、回答或加密推理。

- 全量保留窗口：**2026-08-27 00:00:00 至 2026-11-12 00:00:00，UTC+08:00**，左闭右开。
- 近 30 天窗口：**2026-10-13 00:00:00 至 2026-11-12 00:00:00，UTC+08:00**。
- 时间条件：请求开始时间不早于窗口起点，且 `timestamp_ms + latency_ms` 严格早于截止点。使用完整日期，避免将统计期间正在执行的聊天混进本轮结果。
- 通道和模型：`provider='codex'`，请求模型名称匹配 `gpt-[0-9]*`。
- 成功生成：`failed=0`、`canceled=0`、`generate=1`、时延非负，且推理 token 为非负整数。这里的“成功”来自用量记录，不单独证明客户端收到回答。

完整记录及捕获时间见[汇总 JSON](evidence/reasoning-pattern-2026-11-12.json)。实际保留历史可能受本机采集、导入与清理影响；这些日期不是对所有请求都完整采集的保证。

## 分母与计算公式

README 只展示 **GPT-6 Astra 和 GPT-6.1 Sol**，统一以这两个模型的全部成功生成次数作为分母：**3,735 / 24,319 = 15.36%**。本文件保留原来的完整历史统计：六个模型合计为 **3,856 / 31,710 = 12.16%**；只看推理 token 大于 0 的记录时为 **13.95%**。模型范围或分母不同，比例也会不同。

令 `r = reasoning_tokens`。命中条件为：

```text
r >= 516 且 (r + 2) % 518 == 0
```

主比例使用 `r>0` 的记录作为分母，另列包含 `r=0` 的比例，避免隐藏零值记录。仅靠这张表不能区分零值为何出现，也不能把未观测到的推理用量当成有推理样本。

| 窗口 | 成功生成记录 | 有推理用量的记录 | 零推理记录 | 命中数 | 占有推理用量的记录 | 占全部成功生成 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 全量保留窗口 | 31,710 | 27,638 | 4,072 | 3,856 | 13.95% | 12.16% |
| 近 30 天 | 17,205 | 15,024 | 2,181 | 2,246 | 14.95% | 13.05% |

全量的 31,710 条中，OAuth 为 31,566 条，API key 为 144 条；近 30 天分别为 17,061 和 144 条。多个推理档位混在同一统计内，没有进行任务、模型或档位的等权抽样。

## 按模型分组

模型名称是请求记录中的名称，不是对实际路由模型身份的独立验证。全量有 19,405 条填入了 `response_model`，近 30 天为 17,205 条；这些已填值都与请求模型相同，其余记录没有提供这项核对条件。

| --- | ---: | ---: | ---: | ---: |
| `gpt-6-astra` | 3,409 / 19,817 | 17.20% | 2,209 / 14,696 | 15.03% |

| `gpt-6.1-sol` | 326 / 1,117 | 29.19% | 37 / 224 | 16.52% |

## 怎样理解这些比例

- 单位是**上游生成记录**，包含 Reflow 追加的轮次，不是独立用户、聊天、任务或首轮请求。用量表不足以可靠区分每条记录是首轮还是续接轮。
- 这是一套部署的保留历史，混合插件开关、不同版本、模型、任务和推理档位；不能把它当成无插件基线，也不能拿模型之间的比例直接比较能力。
- 多条记录可能属于同一聊天或同一任务，不能假定它们相互独立。因此不提供基于独立随机抽样假设的置信区间。
- 数字命中本身不能证明发生内部截断、回答变差或续接有效；这里不读取回答、任务评分或推理内容。
- 统计截止于整合版发布前，没有把这些历史请求归为 dev.6 / CPA 0.1.4 的实测成绩。

## 在自己的记录上复现

使用[统计脚本](../scripts/summarize-reasoning-pattern.py)，替换私有数据库路径和时间范围。输出路径必须尚不存在，以保留历史快照：

```sh
python scripts/summarize-reasoning-pattern.py --database /path/to/private/usage.db --since 2026-08-27T00:00:00+08:00 --until 2026-11-12T00:00:00+08:00 --output reasoning-pattern.json
```

脚本用 `mode=ro` 和 `PRAGMA query_only=ON` 打开数据库，在一个读事务内计算两个窗口，仅选取聚合值。它适用于这份记录使用的 `usage_events` 字段结构；其他采集器的字段含义需要先核对。

合成数据检查覆盖公式、两种分母、默认档位、排除条件、开始/完成时间边界、重复标识、空样本及只读访问：

```sh
python scripts/test-reasoning-pattern.py
```

本轮 9 项检查通过；统计只读取现有记录，真实模型调用为 0。
