# Reflow 开源准备与证据

Reflow 已从 CPA 插件提取为独立核心，并为 Codex CLI、Pi 和 Magpie 准备了接入方式。当前是本地开发成果，尚未公开发布。已有原生登录的有限实测，尚无质量改善结论或外部用户反馈数据。

## 计划定位

[Codex for Open Source 官方说明](https://developers.openai.com/community/codex-for-oss)（2026-10-27 重新核对）面向核心维护者和广泛使用的公开项目，也允许其他项目解释其生态价值。支持内容包括六个月 ChatGPT Pro with Codex、按条件提供的 Codex Security，以及用于核心开源工作的 API 额度；页面明确支持 Pi 等其他客户端。

工程判断是：跨生态适配能拓宽 Reflow 的用途，但不是计划的官方先决条件，也不保证入选。申请时应说明已经解决的维护问题、可复现结果及后续维护用途，不把本地适配数量写成社区采用量。

已按 [官方申请表](https://openai.com/form/codex-for-oss/) 的三段 500 字符限制准备 [本地申请草稿](OSS-APPLICATION-DRAFT.md)。项目价值、API 用途和补充说明分别为 466、373、461 字符。尚未填写个人信息、公开仓库链接或选择支持项目，也未提交申请。

独立仓库的首次公开动作另有 [源码预览方案](PUBLICATION-PLAN.md)：固定待审提交，先准备本地源码包和构件校验，再按用户授权创建公开仓库并推送。正式 Release、商店、上游 PR 和申请分别处理。

具体兼容范围见 [兼容性说明](COMPATIBILITY.md)，验证散列和证据见 [dev.4 初始记录](VERIFICATION-0.1.0-dev.4.md)与 [app-server 补充记录](APP-SERVER-2026-10-27.md)。后端恢复会话通过不能证明 dot 入口可见。旧 CPA 版的发布与使用情况应单独核实、单独列出，不能充当独立版的使用数据。

共享入口与 CI 范围见 [回归说明](REGRESSION.md)，Magpie 已知失败的源码线索见 [基准排查](../adapters/magpie/BASELINE-TRIAGE.md)。CI 草稿尚未对外执行，排查笔记尚未转化为上游 issue。

原生登录实测已经观察到一次续接，两个输出文件均通过 9/9 检查，但开启组会话超时，因此整体验收未完成。申请材料应同时写明这一限制，不能将局部成功写成全部通过。见 [实测记录](LIVE-SMOKE-2026-10-26.md)。

修复版在 2026-10-27 的 NDJSON 和后续拓扑排序真实诊断中均正常完成，分别评分 9/9 和 8/8，工具失败事件为 0；两次都没有触发续接。累计 7 次会话、40 次推理请求、1 次续接；仍无完整续接验收或质量改善结论。见 [最新证据](LIVE-TOPO-2026-10-27.md)。

Windows 原生文件编辑探针曾在两版官方 CLI 中失败，已定位到 helper 遗漏 `SYSTEMROOT`，并找到 OpenAI 已合并的修复。加入该修复的本地源码构件通过了五个写入场景及原生协议、插件回归。保存的复现和上游回移补丁属于兼容性排查证据，不能算作本项目新提交的上游修复；也不能当作官方版本或真实账号整体验收。该探针独立于默认回归。见 [离线复现](NATIVE-WRITE-PROBE.md)。

## 后续顺序

先在用户单独授权后，用真实账号运行隔离目录中的小规模连通与开关对照测试。只比较完整成对结果；没有观察到续接时，记录为未触发，不能据此宣布续接验收通过。随后单独安排 Desktop/dot 实际验收。

仓库文档、工作流草稿、发布说明和 PR 内容可先在本地准备。创建公共仓库、推送、发布、提交上游 PR、商店上架和提交申请，分别取得相应授权后再执行。现有 CPA/ECPA/Codex 生产配置保持不变。
